กลับไปเข้าสู่ระบบ UAT

การปิดและลบข้อมูล Always-On Private UAT

ร่าง UAT เท่านั้น — มีผลหลังอนุมัติ bytes/SHA-256 และ consent ที่เกี่ยวข้อง · deletion-social-always-on-uat-2026-10-28-rc4

1. เหตุเริ่ม cleanup

ไม่มี automatic 22:00 shutdown และไม่ใช้วัน kickoff เป็นวันปิด ขณะ UAT เปิดให้คงข้อมูล/เซสชันที่จำเป็นได้ Cleanup เริ่มเมื่อเจ้าของบันทึก actual explicit close, participant ถอนตัว, enrollment ถูกเพิกถอน หรือ safety incident ต้องปิด ระบบต้องบันทึกเหตุและเวลาจริงโดยไม่เผย raw account reference/token

2. ปิดบริการ

ปิด gate Social/Discovery/Chat/Presence และ enrollment ตามขอบเขตที่ปิด เพิกถอนคำเชิญค้างและ provider-linked sessions คง Media/Gallery, public/youth, Sensitive, OTP, Demo, Admin และ Production ปิด ตรวจสอง-person allowlist และ foreign-key ก่อน cleanup

3. Logical cleanup ภายในเจ็ดวัน

ลบหรือทำให้พ้นการใช้งานโปรไฟล์ ตำแหน่ง/Discovery, Chat/read state, Presence, block/report, acceptance/lifecycle และ identity/session ตาม consent และ schema ที่ตรวจสอบ ใช้ D1 transaction/cascade, bounded retries และ foreign-key check หากล้มเหลวให้ retry หรือยกระดับ ห้ามรายงาน PASS จนตรวจจำนวนและ FK ได้ Participant A ห้ามลบบัญชีอัตโนมัติ Participant B ลบบัญชีได้ตาม consent แยก แต่ห้ามลบขณะยัง enrolled/ใช้งานอยู่; ต้องปิด enrollment/session ก่อน

4. R2

R2 private และ Media ปิด จึงไม่ควรมีวัตถุใหม่ หากพบให้ถือเป็น defect/incident ระบุ provenance ก่อนลบ ใช้ bounded cleanup/retry และห้ามลบ bucket หรือวัตถุที่ไม่ทราบที่มา

5. หลักฐาน 90 วัน

เก็บเฉพาะ minimized security/audit evidence ที่จำเป็นอย่างเคร่งครัด เช่น policy/version/hash, consent/close digest, invitation replay protection, security event และ cleanup result เป็นเวลา 90 วันจาก actual close ไม่เก็บ full Chat, location, raw account reference, credential, Media หรือโปรไฟล์เพื่อ audit เมื่อหมดอายุ Worker ลบหลักฐานสดตามกลไกที่ตรวจสอบแล้ว

6. Backup/Time Travel

Cloudflare backup, D1 Time Travel และ recovery copy อาจอยู่นานกว่า logical cleanup และอาจลบรายแถวไม่ได้ เจ็ดวัน/90 วันไม่ใช่คำมั่น physical erasure หากกู้คืนต้องคงข้อจำกัดเดิม ทำ cleanup ซ้ำก่อนใช้ และห้ามทำให้ข้อมูลที่ควรลบกลับมาให้บริการ Social

7. การดูแล

ผู้ดูแลหลักตรวจ 19:00–22:00 Asia/Bangkok ไม่มี backup หรือ 24/7 monitoring คำขอนอกช่วงเข้าคิว ไม่รับประกันเวลาตอบและ ChatGun ไม่ใช่บริการฉุกเฉิน
