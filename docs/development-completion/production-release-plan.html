Deployment guard

แพ็กเกจใหม่ประกาศ requiredD1MigrationNumber=17 ตัว deploy ตรวจ schema และต้องมี approval ส่วนตัว full-system-uat-approval.json ที่ระบุ exact SHA, humanUatPassed, rolloutApproved, productionMigrationsApproved เป็น true หลังการอนุมัติจริงเท่านั้น ไม่มีการสร้าง approval นี้อัตโนมัติ การอนุมัติ owner pilot เดิมใช้ข้าม gate นี้ไม่ได้

เปิดเฉพาะ flags ที่อนุมัติสำหรับรายชื่อทดสอบ Public signup/Sensitive/identity evidence/OTP/Game/Demo ยังคงปิด ไม่เพิ่มสมาชิกจริงหรือขยาย Admin grant เงียบ ๆ

หลัง deploy ที่ได้รับอนุมัติ

  1. ตรวจ live domain, JSON APIs, release SHA และ manifest hashes จริง ไม่ใช้เพียง CLI deployment success
  2. ตรวจ genuine auth/session, RBAC, privacy/block/grant boundaries, moderation/quarantine และ resource usage ในขอบเขตอนุมัติ
  3. บันทึกข้อผิดพลาด/queue health/cleanup retries และคนรับผิดชอบ ไม่อ้าง monitoring 24/7 หรือ paging ที่ยังไม่ได้ตั้งค่า

Rollback / recovery

เมื่อมี critical failure ให้ปิด Social/media/Presence/rating และ restricted moderation capabilities ที่กระทบก่อน ใช้แพ็กเกจปลอดภัยที่ตรวจแล้วโดยรักษา D1/R2 และ authentication ของ owner pilot ห้าม downgrade schema, reset tables, ลบสมาชิก, restore ทับข้อมูลใหม่ หรือ rollback ไปโค้ดที่ไม่ปลอดภัยพร้อมเปิดสื่อจริง ไม่ทำ destructive recovery โดยไม่มีอนุมัติและ reconciliation plan

Migration additive สามารถคง columns/tables ไว้ระหว่างปิดบริการได้ อย่าใช้ down migration ลบข้อมูลเพื่อให้โค้ดเก่าทำงาน ต้องตรวจ compatibility ของ rollback artifact กับ schema และ feature flags ทุกครั้ง
