แนวทางผู้ดูแลคนเดียว · รอบเจ้าของบัญชี

20 ตุลาคม 2026 · Asia/Bangkok · เอกสารภายในสำหรับเจ้าของตรวจทาน ไม่ใช่นโยบายที่เผยแพร่ต่อสมาชิก และไม่ใช่การรับรองการปฏิบัติตามกฎหมาย

สิ่งที่อนุมัติแล้ว

เจ้าของยืนยัน UUID ผ่านเอกสารในเครื่องและอนุมัติ report_reviewer + safety_admin เป็นเวลา 7 วัน มีเหตุผลและประวัติการให้สิทธิ์แยกกันสองรายการ ไม่มีสิทธิ์ moderation_admin หรือ identity_reviewer เปิดเฉพาะเครื่องมือดูแลหลังผ่าน CI/Preview ไม่ได้อนุมัติเปิดบริการสังคมหรือสื่อ

เวลาที่เจ้าของอนุมัติ: ทุกวัน 19:00–22:00 น. Asia/Bangkok รวม 21 ชั่วโมงต่อสัปดาห์ ไม่มีผู้ดูแลสำรองและไม่มีบริการเฝ้าดู 24 ชั่วโมง ขณะนี้มีสมาชิกจริงเพียงเจ้าของ 1 คน เจ้าของเลือกทำระบบผู้ดูแลต่อก่อนโดยยังไม่มีผู้ทดสอบคนที่สอง

ขั้นตอนปฏิบัติ

  1. เปิด /app/moderation.html ด้วยบัญชีที่ได้รับสิทธิ์ ภาพรวมไม่ต้องกรอก Purpose ระบบบันทึก routine_admin_dashboard_access อัตโนมัติ
  2. ตรวจจำนวนสมาชิกจริง งาน Critical/High อายุงาน คิวสื่อ รายงาน อุทธรณ์ และคิวลบก่อนงานทั่วไป ตัวเลขศูนย์ไม่ใช่หลักฐานว่ามีเจ้าหน้าที่เฝ้าดูตลอดเวลา
  3. ก่อนเปิดคิวที่จำกัดหรือหลักฐาน ให้เข้าสู่ระบบใหม่เมื่อเกิน 10 นาที และระบุวัตถุประสงค์เฉพาะกรณี ไม่ใส่รหัสผ่าน โทเคน หรือเนื้อหาส่วนตัวที่ไม่จำเป็นในเหตุผล
  4. การตัดสินรูปต้องเป็นการตรวจของมนุษย์ บันทึกเหตุผลและรุ่นข้อมูล General อาจปล่อยได้ตามขอบเขตที่อนุมัติ Prohibited ต้องปฏิเสธ Sensitive ยังห้ามส่งให้สมาชิก ไม่เปิดผู้ให้บริการสแกนโดยไม่มีการอนุมัติ
  5. เมื่อเกิดเหตุเสี่ยง ให้จำกัดการเผยแพร่และการติดต่อก่อน เก็บหลักฐานเท่าที่จำเป็น ไม่ดาวน์โหลดหรือส่งต่อรูปต้องสงสัยไปยังแชท อีเมล หรือ GitHub
  6. ปิดรอบเวลา 22:00 โดยบันทึกงานค้างและมาตรการจำกัดความเสี่ยง หากเจ้าของไม่พร้อมทำงาน ให้หยุดรับสมาชิกหรือความสามารถที่เกี่ยวข้อง ไม่เรียกกล่องรับรายงานว่าเป็นการเฝ้าดู

ความรุนแรงและข้อจำกัด

ระดับตัวอย่าง/วิธีจัดการเมื่อพบ
Criticalภัยคุกคามใกล้เกิดอันตราย ประเด็นเด็ก หรือภาพไม่ยินยอม: จำกัดการเข้าถึง เก็บข้อมูลให้น้อย ใช้ช่องทางฉุกเฉิน/กฎหมายที่เจ้าของอนุมัติ ห้ามสืบสวนหรือเผยแพร่เอง
Highละเมิดความเป็นส่วนตัว ตำแหน่ง หรือความรุนแรง: ป้องกันการเข้าถึงต่อเนื่องและส่งต่อการตัดสินที่เหมาะสม
Medium/Lowคุกคาม แอบอ้าง สแปม: ตรวจหลัง Critical/High ตามอายุงาน บันทึกเหตุผลและผลการตัดสิน

การจัดระดับอัตโนมัติเป็นเพียงตัวช่วยจัดคิว ไม่ใช่ผลการตัดสินทางกฎหมาย ไม่สัญญาเวลาตอบกลับที่ยังไม่ได้รับอนุมัติ

ส่วนที่เตรียมใน Staging เท่านั้น

Migration 0016 และ ACCOUNT_MODERATION_ENABLED สำหรับระงับสิทธิ์ Beta ตามรายงาน ไม่ลบบัญชี: เพิกถอนเซสชัน ซ่อนและล้างตำแหน่ง ยกเลิกสิทธิ์อัลบั้มส่วนตัว มีการอุทธรณ์ที่ต้องยืนยันตัวตน มี revision ป้องกันคำขอซ้ำ การคืนสิทธิ์ไม่คืนตำแหน่งหรือสิทธิ์อัลบั้มเดิมโดยอัตโนมัติ หากผู้ตัดสินเดิมพิจารณาอุทธรณ์ ต้องรับทราบข้อขัดแย้งอย่างชัดเจนและไม่อ้างว่าเป็นการทบทวนอิสระ

Production ยังอยู่ Migration 0015 และ flag นี้ปิด การนำส่วนนี้ไป Production ต้องอนุมัติ migration/ขอบเขตการปฏิบัติและการจัดเก็บประวัติ ไม่ใช้การให้สิทธิ์ผู้ดูแลเป็นการอนุมัติระงับบัญชีจริงโดยอัตโนมัติ

ก่อนเปิดบริการให้คนที่สอง

  • ระบุและอนุมัติผู้ใหญ่คนที่สองเป็นรายบุคคล พร้อมความยินยอม สิทธิ์ LINE Admin/Tester และเกณฑ์อายุในรอบทดสอบ ห้ามสร้างบัญชีเจ้าของซ้ำ
  • ตรวจและอนุมัติคำชี้แจง/ขอบเขตนโยบายสำหรับการทดสอบสองคน เนื้อหาที่เผยแพร่ปัจจุบันอนุมัติเฉพาะรอบเจ้าของ
  • กำหนดช่องทางรับรายงาน ช่องทางแจ้งเตือนส่วนตัว ช่องทางฉุกเฉิน/ผู้เชี่ยวชาญกฎหมาย ขั้นตอนกรณีเจ้าของไม่อยู่ และการอุทธรณ์ที่มีผู้ตัดสินคนเดียว ต้องอนุมัติก่อนเปิดแชทหรืออัปโหลด
  • กำหนดจำนวนผู้เข้าร่วมอย่างชัดเจน ไม่ให้ระบบเลือกจำนวนเอง คำเชิญใช้ครั้งเดียว 30 นาที ส่งผ่านช่องทางส่วนตัวเท่านั้น
  • เปิดแต่ละ flag เมื่อผ่านการทดสอบผู้ใช้จริงสองคนและได้รับอนุมัติแยก ไม่ถือว่า unit test หรือ mock browser คือ genuine E2E

ข้อมูลและการกู้คืน

มีสำรอง Production ก่อนให้สิทธิ์ในพื้นที่ส่วนตัว 0700/0600 พร้อมทดสอบนำเข้า SQLite และ bookmark ของ D1 ไม่เก็บ SQL/UUID/โทเคนใน repository ใช้ D1/R2 ของ ChatGun เท่านั้น ห้ามกู้ฐานข้อมูลทับข้อมูลจริงหรือลด schema โดยไม่มีคำอนุมัติเฉพาะเหตุ ก่อนอัปโหลดต้องตรวจ cleanup Worker/คิว retry/retention จริง และไม่รับรองว่าลบจาก backup/Time Travel ได้ทันที

เมื่อมีเหตุ ให้ปิด flag ที่เกี่ยวข้องก่อน รักษาข้อมูลจริง ใช้แพ็กเกจรุ่นที่ตรวจแล้วเพื่อ rollback แอปได้โดยไม่ลบฐานข้อมูล หากจำเป็นต้องเพิกถอนสิทธิ์บัญชีจริง ใช้กระบวนการที่บันทึกเหตุผลและอนุมัติไว้ ไม่แก้ตารางเงียบ ๆ

ต้นทุนและการติดตาม

ใช้ _routes.json เฉพาะ /api/* เพื่อให้ไฟล์ static ไม่เรียก Functions ไม่มีการซื้อหรืออัปเกรดแผน API ส่วนตัวห้าม cache แบบสาธารณะ หน้าที่ไม่แสดง/เบื้องหลังไม่ควร poll ส่วนที่ไม่ได้ใช้ โปรไฟล์สาธารณะที่ไม่มีรูปและปิดทั้ง Chat/Upload ไม่อ่าน Gallery ทุก 10 วินาที สถานะและรูปส่วนตัวที่เปิดใช้งานยังตรวจสิทธิ์ตามเดิม

ตัวเลข adaptive analytics เป็นค่าประมาณล่าช้า ไม่ใช่ใบเรียกเก็บเงินจริงหรือหลักฐานสิทธิ์แพ็กเกจ ปัจจุบันไม่มีระบบ paging 24 ชั่วโมง ก่อนเพิ่มคนให้ดู usage จริงและโควตาจาก Workers, D1 และ R2 อีกครั้ง ไม่อนุมานว่าระบบจะฟรีตลอดจากผู้ใช้ทดสอบจำนวนน้อย

ยังต้องตัดสินใจ

ผู้ดูแลสำรอง, ช่องทางแจ้งเตือน, เส้นทางฉุกเฉิน/กฎหมาย, การจัดการอุทธรณ์ที่มีผลประโยชน์ทับซ้อน, retention ของเหตุผลและประวัติการระงับ, scope นโยบายสำหรับบุคคลอื่น, ผู้ทดสอบคนที่สอง และขอบเขตเปิดฟีเจอร์ ยังไม่อนุมัติในรอบนี้
